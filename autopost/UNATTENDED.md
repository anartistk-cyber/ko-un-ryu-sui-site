# 無人実行の約束と「OK待ち」の出し方（2026-11-17 作成）

目的：藤津さんが画面の前にいなくても、改善と点検が止まらず進むこと。ただし、外のサービスや公開内容に影響することは、スマホから「OK」をもらってから実行する。
自動実行（定期タスク）も、対話の回も、この約束に従う。

## 1. 3つに分ける
**A 自動でやる（OK不要）**
- 読み取り：Search Console・GA4・GBP のパフォーマンス・PageSpeed・本番ページの確認。
- 3サイトのコード・文章・FAQ・ブログの改善と公開。事実は FACTS.md の範囲。ビルド・公開ゲート・点検（overflow／audit）を通ったものだけ。
- 記録：IMPROVEMENT_LOG・reports・Docs の分析レポート。リポジトリへの反映（git fetch → ff-merge → push）。

**B OK待ち（キューに入れて通知する）**
- 外部サービスの設定・内容の変更：Google ビジネスプロフィール、ホットペッパー、SalonAnswer のデータ・設定、LINE 公式、Xserver／DNS／WordPress、GA4・Search Console の設定。
- 投稿・返信・メッセージの送信（SNS、GBP、LINE、メール）。
- アカウント作成・契約・支払い（例：Manus の更新・解約）。
- FACTS.md に無い事実（料金・条件・対応可否）が要る公開内容。
- データの削除。

**C OKが出てもしない（藤津さん本人の操作）**
- パスワード・カード番号の入力、ログイン操作、CAPTCHA、支払い・送金・売買。
- DNS・サーバーのアクセス制限などの保存ボタン（入力の準備までは行い、保存は藤津さんが押す。従来どおり）。

## 2. OKが要ることに出会ったら（無人の実行）
1. その作業だけ止めて、ほかの作業は続ける（全部は止めない）。
2. `autopost/APPROVALS.md` の「OK待ち」に1件足す：番号・やること（1行）・理由（数字）・実行の手順（そのまま実行できる形）・影響と元に戻し方・期限・出典。
3. 新しい件が増えたときだけ PushNotification を送る（`<routine_summary>` で囲む。先頭は「OK待ち N件：…」。1行・200字以内）。増えていない回、正常に終わった回は通知しない。
4. 記録して push（fetch → ff-merge → push）。

## 3. スマホからのOKの出し方
- 通知が来たら、Claude アプリで「行雲流水」の会話（このリポジトリを扱っている会話）を開き、「OK 3」「OK 1・2」「見送り 4」「2は文面を〇〇に変えて」と返信する。
- 受けた側は APPROVALS.md を読み、OKが出た件だけを実行する。実行の前に現状を読み直し、OKを待つ間に状況が変わっていたら止めて報告する。実行後は結果を確認し、状態を「済」にして IMPROVEMENT_LOG に1行（番号・時刻・何を・戻し方）。
- OKの範囲は、その1件に書かれたとおり。宛先・金額・設定を足さない。「OK 全部」は、その時点で並んでいる件だけ（あとから足された件は含めない）。
- ブラウザ操作が要る件は、PC がつながっているときだけ実行できる。つながっていなければ状態を「PC待ち」にして残す。

## 4. 無人でできること／PCが要ること
- クラウドだけで足りる：リポジトリ（サイトのコード・文章・ブログ）、WebSearch、記録、Docs。
- PC とログイン済みブラウザが要る：Search Console・GA4・GBP・PageSpeed・SalonAnswer・SALON BOARD・LINE 管理画面・Xserver。PC の電源が入り、Claude アプリが開いていて、各サービスにログイン済みであること。ログインが切れていたらパスワードは入力せず、「ログイン待ち」として通知する（ログインは藤津さん）。
- クラウドだけで動いた回に Chrome が無いときは、取れない項目を「未取得（理由）」と書き、数字を推測しない。取れなかった項目は、PC がつながる次の対話の回で取り直す。
- 設定（藤津さんが1回だけ）：定期タスクの設定画面で「このパソコンを必須にする」と「自動承認」。既存タスクのこの設定は、Claude 側からは変えられない。

## 5. 通知の使い分け
- すぐ通知：OK待ちが新しく出た／ログイン切れ・PC未接続で取得に失敗した／サイトが開けないなどの異常。
- 通知しない：正常に終わった回、前回と変わらない回。
