# glow ブログ自動投稿 RUNBOOK
1. glow-site/autopost/FACTS.md だけを事実の根拠にする。検索で得た一般知識は「髪・ヘアケアの一般論」に限り、効果の断定・医療的表現・他店比較は禁止。
2. 週3回（火・木・土）1本（2026-11-18 藤津さん指示）。曜日テーマは下の「曜日テーマ」に従う。ターゲットは素髪をきれいにしたい10〜20代女性。テーマは 泉大津/和泉/高石/堺/岸和田などの地域×悩み（朝ラク・カラー・パーマ・髪質改善・ヘッドスパ・ショート）。1500〜2500字、h2を3〜5個、末尾で予約導線。
3. glow-site/data.json の posts に追加（slug, type=ブログ|お知らせ, date, title, desc, image(uploads相対: 2026/04/glow_img-08.jpg 等), alt, body[{p|h2|ul}]）。画像は既存の glow_img-05/08/10, staff_3 のみ使う。
4. cd glow-site && node build.mjs（出力 glow-site/site）→ manifest.json 再生成:
   cd site && find . -type f ! -name manifest.json | sed 's|^\./||' | sort | while read f; do printf '%s\t%s\n' "$f" "$(sha256sum "$f"|cut -d' ' -f1)"; done | python3 -c "import sys,json;print(json.dumps({'files':[dict(zip(('path','sha256'),l.rstrip('\n').split('\t'))) for l in sys.stdin]},ensure_ascii=False,indent=1))" > manifest.json
5. git commit & push main。サーバー側 sync_gl.php が毎時取り込む（公開まで最大1時間）。
6. 毎週土曜は口コミ(★5)の追加抜粋、料金・営業の変更確認、リンク切れ確認を行う。

## 曜日テーマ（2026-11-18 開始。数字を見て入れ替える）
- 火＝髪のお悩み解決（地域×悩み。乾燥・くせ毛・広がり・朝ラクなど）。タグ #髪のお悩み
- 木＝メニュー・相談のしかた（カラー・パーマ・髪質改善・ヘッドスパの選び方）。タグ #髪質改善 など該当メニュー
- 土＝スタイル・おでかけ（ショート・ヘアセット・季節のスタイル）。タグ #ヘアスタイル #ヘアアレンジ
- 共通タグ：#glow泉大津 #泉大津美容室 #泉大津駅。記事の地域に合わせて #和泉 #高石 #堺 #岸和田 の地域タグを足す。
- ハッシュタグはブログ本文には入れず、記事ごとに Instagram 用の下書き（キャプション＋タグ）を glow-site/autopost/sns/<slug>.md に置く。投稿は外部への発信なので autopost/APPROVALS.md の「OK待ち」に入れ、藤津さんの「OK 番号」を待つ（自動投稿しない）。
- 同じテーマを続けず、直近のslugと重複しないこと。

## 画像・動画
- 既存写真（glow_img-05/08/10, staff_3）に加え、記事ごとに内容に合わせた文字入りカード（glowの配色のイラスト調）など複数パターンを作って使ってよい。人物が写っている（見える）画像、glowの店内の雰囲気に合わせた画像もOK（2026-11-18 藤津さん了承）。ただし次は守る：①施術のビフォーアフター・仕上がりの実績として見せない（イメージ画像として使う）②実在のお客様の口コミ・体験談に見せかけない③キャスト個人の顔を生成画像で再現しない（キャストの写真は /cast/ の実写のみ）④「実際の店内写真」と書かない（alt・キャプションは「イメージ」）。
- 動画は記事の要点を見せる15秒の縦動画（Instagramリール用の下書き）。作成・投稿は藤津さんのOK後。

## データの記録と見直し
- 公開のたびに glow-site/autopost/POST_LOG.md に1行：日付・曜日・テーマ・slug・タグ・画像の種類。
- 週次（日曜の分析）で、テーマ別・曜日別に 閲覧数・検索流入・予約ボタン（cta_*）のクリックを POST_LOG の列に追記する。取れない数字は「未取得」と書き、推測しない。
- 4週ごとに、数字の良いテーマを増やし、反応の薄いテーマは切り口を変える（変更は POST_LOG に理由を書く）。
